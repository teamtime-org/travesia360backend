# Reglas de Arquitectura de Software - TeamTime .NET Backend

## CONTEXTO
Este proyecto utiliza .NET 8 con Clean Architecture, CQRS pattern, Entity Framework Core y ASP.NET Core Identity.

## REGLAS OBLIGATORIAS - NO NEGOCIABLES:

### 1. UNA CLASE POR ARCHIVO
- Crear exactamente una clase por archivo
- El nombre del archivo debe ser idéntico al nombre de la clase con extensión .cs
- Ejemplo: CustomerService → CustomerService.cs
- Nunca colocar múltiples clases, interfaces o estructuras en el mismo archivo

### 2. CÓDIGO SIN ERRORES
- Todo el código debe compilar completamente sin errores ni advertencias
- Verificar que todos los tipos estén definidos
- Todos los namespaces importados con using statements correctos
- Sin errores de sintaxis

### 3. IMPLEMENTACIÓN COMPLETA OBLIGATORIA
- Prohibido usar `throw new NotImplementedException()`
- No dejar métodos vacíos
- No colocar comentarios TODO o HACK
- Cada método debe tener su lógica completamente implementada y funcional

### 4. CONVENCIONES DE NOMENCLATURA C#
- **PascalCase**: clases, interfaces, métodos públicos, propiedades y eventos
- **camelCase**: parámetros, variables locales y argumentos
- **underscore + camelCase**: campos privados (`_fieldName`)
- **Interfaces**: siempre comenzar con `I` mayúscula (`IUserService`)
- **Métodos asíncronos**: terminar con sufijo `Async` (`GetUserAsync`)

### 5. USING STATEMENTS COMPLETOS
- Todos los using statements necesarios al inicio del archivo
- No asumir que están implícitos
- Incluir: `System`, `System.Collections.Generic`, `System.Threading.Tasks`, `System.Linq`

## REGLAS IMPORTANTES - APLICAR SIEMPRE QUE SEA POSIBLE:

### 6. MANEJO DE EXCEPCIONES
```csharp
try
{
    // Operaciones que pueden fallar: I/O, BD, red, parseo, conversiones
    var result = await riskOperation();
    return result;
}
catch (SpecificException ex)
{
    // Manejar apropiadamente, no tragar silenciosamente
    throw new BusinessException("Error específico", ex);
}
```

### 7. VALIDACIÓN DE PARÁMETROS NULOS
```csharp
public UserService(IUserRepository userRepository)
{
    _userRepository = userRepository ?? throw new ArgumentNullException(nameof(userRepository));
}
```

### 8. MÉTODOS ASÍNCRONOS
```csharp
public async Task<User> GetUserAsync(Guid id)
{
    // Siempre usar async/await correctamente
    // Retornar Task o Task<T>
    // Evitar async void excepto en event handlers
}
```

### 9. INYECCIÓN DE DEPENDENCIAS
```csharp
public class UserService
{
    private readonly IUserRepository _userRepository;
    private readonly ILogger<UserService> _logger;

    public UserService(IUserRepository userRepository, ILogger<UserService> logger)
    {
        _userRepository = userRepository ?? throw new ArgumentNullException(nameof(userRepository));
        _logger = logger ?? throw new ArgumentNullException(nameof(logger));
    }
}
```

### 10. SEPARACIÓN DE RESPONSABILIDADES
- Una clase no debe exceder 300-500 líneas
- Si hace demasiado, dividir en múltiples clases con responsabilidades específicas

## ESTRUCTURA Y ORGANIZACIÓN:

### Orden de elementos en archivo:
1. Namespace
2. Using statements (si son necesarios dentro del namespace)
3. Declaración de clase o interface
4. Campos privados
5. Constructores
6. Propiedades públicas
7. Métodos públicos
8. Métodos privados

### Namespaces:
```csharp
namespace TeamTime.Application.Services;
namespace TeamTime.Infrastructure.Data.Configurations;
namespace TeamTime.Domain.Entities;
```

## LÍMITES PRAGMÁTICOS:

- **Métodos**: hasta 50-80 líneas si la lógica es secuencial y clara
- **Parámetros**: no más de 7-8 parámetros por método
- **Anidación**: evitar más de 4-5 niveles de profundidad
- **Early returns**: usar para reducir anidación

## PRIORIDADES AL GENERAR CÓDIGO:

1. **Funcionalidad sobre perfección**: código funcional que se puede mejorar después
2. **Claridad sobre brevedad**: fácil de entender para otros desarrolladores
3. **Pragmatismo sobre purismo**: no forzar patrones que no agreguen valor
4. **Código funcionando sobre sobre-ingeniería**: resolver el problema actual

## VALIDACIONES ANTES DE ENTREGAR CÓDIGO:

- [ ] Cada clase está en su propio archivo
- [ ] No hay métodos con NotImplementedException o sin implementar
- [ ] El código compila sin errores
- [ ] Los nombres siguen las convenciones de C#
- [ ] Las operaciones riesgosas tienen manejo de excepciones
- [ ] Los constructores validan parámetros nulos cuando es crítico
- [ ] Los métodos asíncronos tienen el sufijo Async
